# 原文件协作入口

只传当前已授权任务确实需要的选定文件。Codex 在已授权目录内发现必要附件并生成请求，用户不用选文件或修改 JSON。缺材料时通过结果通道请求 Codex 补充。双方使用当前账号自己的固定私有结果服务；没有正式附件工具时先完成该账号的服务配置，不用其他人的地址或凭据。

请求增加 `attachments: [{path: 'diagram.png', mimeType: 'image/png'}]`；path 是授权目录根相对路径。只需接收 Chat 生成文件时增加 `receiveAttachments: true`。prepare.mjs 自动读取选定文件并计算大小和完整哈希，不递归扫描目录。整个文件不适合传输时由 Codex 提供必要正文片段，注明准确行范围和整文件版本。

由 [统一宿主入口](host-entry.md) 自动初始化本机文件 IO 并完成传输。图片生成设 imageGeneration=true 和 imagePrompt：先只发送具体画面要求，程序核对原消息、发送窗口和结束线索后，再单独发送一次原图导出指令。

传输期间只读预取最多 3 块，写入始终有序，桥接代码不超过 64,000 字节。所有原文件保留完整大小/哈希和任务/版本/回执核验；禁止目录越界、敏感路径、junction/symlink、覆盖和版本变化。下载完成清理本轮附件并确认不可读。

单文件最大 16 MiB，服务分块上限 256 KiB；本机 JS 桥接采用更小分块以符合工具审查上限，不通过其他通道绕过。图片/音频原生预览最大 4 MiB，预览不替代原文件校验。下载不覆盖现有文件，网络保持 HTTPS 和证书校验。

附件上传后一小时失效，读取不续期；访问/明确删除触发物理清理，不保证定时删除。超时或发送不明保留任务原包续等；不无限续期。Chat 无法导出原文件时报告平台限制，不以路径、元数据或替身冒充成功。
