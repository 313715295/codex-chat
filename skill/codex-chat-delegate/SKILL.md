# Codex ↔ Chat 协作

按用户指令或适用项目规则允许的范围使用 Chat，复用已确认的目标和材料目录。在许可范围内自动完成材料传送、补充、等待和结果取回；目标或材料范围无法确定时再询问。

## 材料

- 必要正文直接发送；片段注明整文件版本和准确行范围。
- 原文件按 [文件入口](references/attachments.md) 收发；只需接收生成文件时设 receiveAttachments=true。
- 用户选择生图时设 imageGeneration=true，用 imagePrompt 提供一条画面要求，或 imagePrompts 提供多条。一次只发送一条，上一轮结束后再补发下一张的生图指令；图片由用户在 Chat 查看和下载。不设 receiveAttachments，不追加导出或催交。队列在同一程序内等待，最后一条送达即返回，不把送达记作生图成功。

Chat 返回 needs_materials 时，Codex 在授权目录内补充必要正文或附件，以同一 taskId 的新 revision 继续；重新提供后续仍需要的材料，旧版短期附件可能已清理。无法确定材料、超出范围或缺项重复且无新信息时报告原因。

只传必要材料，保留目录和敏感路径检查。文件名、sandbox 路径或哈希文字不算原文件传输。

## 执行

1. 用 prepare.mjs show 读取本 Codex 会话的账号、私人通道、Chat 和材料目录，原生 read_thread 核对目标。以 Codex 会话为主，同一时刻合作一个 Chat，可按安排更换目标；不同绑定可共用材料目录。未完成任务默认阻止切换；用户要求保留暂停后更换时，按 [宿主入口](references/host-entry.md) 保存并暂停原任务，再绑定新目标。新账号按 [通道初始化](references/own-results-setup.md) 核实并保存；已配置账号用 account-switch 恢复绑定，切换后仍核验真实账号。
2. 按宿主入口调用 job-entry.js。普通审核、规划、文字设计优先由程序查询 get_task_result，不增加前置 Chat 探针；每五分钟仍无结果时才用 read_thread 核对漏交，不以 Chat 停止工作代替正式结果。生图只走原生消息，保留账号、目标和执行锁检查，不登记远程结果任务、不调用附件通道；图片相关异常的按需查探见宿主入口。
3. 核对任务、版本和回执；回传文件下载后校验完整字节与哈希，清理短期附件，再继续当前任务。completed 只覆盖实际完成范围；cleanup.pending 或 executionCleanup.pending 如实报告。
4. 超时加载原包和状态续等；sending/uncertain 不盲目重发，待完成任务不插入新任务或盲目解除锁。图片队列报告已发送/总条数，保留未发送项；旧自动取回图片包不续跑。

空查询、状态核对、图片队列和文件传输留在同一工具程序内，不把空结果交给模型判断或另开查询循环。exec 返回运行中的 cell ID 时只用 wait 续取；需要按宿主要求报告进度时保持简短，不附加检查。skill 不能阻止宿主续取时的模型调用；统计用量须包含这些响应，不能把“程序未调用模型 API”说成“整个等待零模型消耗”。程序不提供常驻后台或闲置会话唤醒。

## 连接与异常

缺少结果或附件工具时读取 [通道初始化](references/own-results-setup.md)，复用本账号私人服务。切换账号后核验当前私人服务所有者与实际工具连接身份；绑定账号不匹配时停止发送，协助本人登录或连接正确账号，不能仅改目标 Chat。

报告具体失败阶段与缺项；本人登录或安全确认按实际页面引导。保留认证和证书校验，遵守执行拒绝。

目标会话报告 systemError 时保留待恢复任务并报告桌面消息故障；回执不明不重发，不把继续空等当成正常处理。
