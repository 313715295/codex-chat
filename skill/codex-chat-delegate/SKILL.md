# Codex ↔ Chat 传输工具

提供消息、材料和结果通道。任务内容、处理方法和是否取回文件由使用者决定；审核、规划、设计和生图只是用法示例。安装或保存绑定不代表要求使用 Chat。

## 发送请求

沿用已确认的账号、目标 Chat 和材料目录。目标不明确或超出授权范围时核对；安排明确后自动选取必要材料，无需用户编辑配置、逐次选择 skill 或搬运结果。

按 [请求写法](references/requests.md) 描述目标、必要上下文和交付要求。业务指令保持简短，协议字段由程序生成；不要手写一长串工具调用步骤，不让 Chat 研究传输实现。需要原文件时见 [附件入口](references/attachments.md)。

生图仅发送画面指令；多张按上一轮结束后逐条发送，最后一条送达即返回。用户在 Chat 查看和下载。用户另行要求取回已有文件时，使用普通收文件请求，不重新生图。

## 执行与恢复

按 [宿主入口](references/host-entry.md) 调用 job-entry.js，完成身份与目标检查、执行占用、发送、等待、下载校验和清理。已有连接复用；首次配置或账号变化见 [通道初始化](references/own-results-setup.md)。以当前 Codex 会话为主，同一时刻合作一个 Chat；更换目标或保留暂停任务按宿主入口处理。

缺项通过 needs_materials 返回，由 Codex 在授权目录补充新 revision。materialsRead 仅是读过的输入，输出文件使用 attachmentIds。文件名、路径或哈希文字不能代替原文件；预览元数据不能证明图像可见或音频可听。

空查询、分块、哈希和队列调度留在同一工具程序内。普通任务查询正式结果，每五分钟无结果再核对对应轮次；不预发能力探针。异常时按需查看已有状态，只有一次实际调用能消除疑问时才发简短探针。exec 返回运行中的 cell ID 时只用 wait 续取，不另开轮询；宿主续取仍可能产生模型请求，不能声称整个等待零消耗。

超时加载原包续等；发送回执不明不重发，待办不抢占。systemError 或工具缺失报告具体阶段并保留恢复状态。仅按实际完成范围报告，清理未完成须说明。保留目录、身份、认证、证书与执行拒绝检查。
