# 验证记录

版本：0.3.7。整理日期：2026-10-15。以下记录区分既有账号历史通过项与新账号接入检查，不代表所有账号均可使用。

## 本次首次接入修复

从公开 v0.3.6 ZIP 解压到新的可写目录，原包 160 项文件哈希核验通过。首次初始化暴露了发布前请求连接信息的顺序错误，以及 Windows 构建包结构、连接发现延迟的处理缺口；本地修复后在同一台机器的新账号下继续完成。

新账号独立私人服务已创建、构建并发布，平台返回 Already installed；随后以实际 MCP 只读探针和原生 owner-private 记录独立核实账号、地址、工具前缀及连接身份，无需用户手动安装。这是使用原 ZIP 加本地修复的接入验证，不是另一台机器对 v0.3.7 的完整验收。

真实审核只发送一次，正式结果尚未返回，目标 Chat 报 systemError，用户也确认页面显示系统错误并要求暂停。设计与图片未启动，多账号真实切换按用户要求延期。程序已补充 systemError 停止等待及保留原任务的回归检查；没有借此重发、清除待办或更改平台权限。

## 既有账号已实际验证

- 文字委托、正式结果提交和 Codex 精确读回；任务、版本、回执及材料 SHA-256 一致。
- 普通审核和文字设计采用结果优先策略后，两轮分别约 50 秒和 2 分 20 秒完成，各发一条委托，无手动选择应用或用户搬运结果。两轮均未达到五分钟，不充当真实兜底故障恢复验收。
- 选定附件上传和读回、完整字节与 SHA-256 校验、任务/版本关联，以及清理后拒绝读取。
- 三条真实生图指令按“古桥对决 → 雪山独行 → 竹林练剑”发送，约 2 分 54 秒返回 sent，3/3 条均有原生回执。前两轮结束后才发送下一条，最后一条送达即退出；独立只读核对确认三条原文与顺序，本地任务占用已释放。
- 生图队列运行内读取轮次 8 次，正式结果查询、自动导出及附件工具调用均为 0。原生历史存在同步延迟，独立验收额外读取 4 次后确认第三条，没有重新发送。

## 图片范围

图片功能由用户选择。程序逐条发送生图指令，用户在 Chat 查看和下载。sent 仅表示指令送达；原生摘要没有提供成图内容，本次未核验实际成图、数量、质量或原文件。

旧版自动图片回传曾有成功记录，后续复测在导出轮反复报告工具不可用；提前添加协作说明也未解决。0.3.6 停用该入口，旧包保留记录，不自动继续生成或导出。此版本不声称修复了自动图片回传。

## 等待与本地检查

普通任务在程序内约每 30 秒查询正式结果，每五分钟仍无结果时核对对应轮次，最多提醒补交一次。图片队列约每 30 秒核对前一轮，空检查不会单独返回模型；两条路径均有时限和恢复状态，回执不明不盲目重发。

程序自身不调用模型 API，宿主续取仍可能产生模型请求。真实三条图片队列执行阶段为 3 次 Codex 响应，其中等待续取 2 次；准备、独立核验和最终报告另计，Chat 内部请求数不可读。没有实现闲置会话事件唤醒。

Windows Node 24.18.0 x64 下，116 项协作测试、12 项附件测试及 MCP smoke 检查通过。模拟检查覆盖首次发布顺序、连接发现延迟、Already installed、Windows 构建包结构、五分钟漏交恢复、Chat 系统错误、图片队列顺序、超时恢复、身份失败和回执丢失。这些不代替真实故障注入或新用户验收。
