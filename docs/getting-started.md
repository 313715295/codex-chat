# 首次安装与日常使用

## 首选：交给 Codex 安装

无需先解压。把 Windows ZIP 附件、本机 ZIP 完整路径或仓库下载链接交给 Codex，说明安装位置、材料目录和目标 Chat 对话链接。

Codex 会核对包的文件哈希和 Node 24.x x64，将包放到新建的可写安装目录，安装本地协作 skill，然后核对当前账号的桌面消息、Sites 和私人应用入口。目录已存在时先查看，不覆盖其他文件。安装目录不自动成为材料目录。

缺 Node 时，Codex 指向 Node 官方安装入口；安装程序及必要系统确认由本人完成。不要为了安装关闭审批、证书校验或安全设置。

首次配置按包内 skill 的自有通道指引进行。Codex 从干净模板初始化当前账号自己的私人服务，生成配置，给出平台返回的固定连接地址，核实实际工具可用并保存本机绑定。平台要求登录、安装/连接应用或授权时，用户完成对应页面动作。没有相关平台能力时会报告具体缺项；当前没有脱离宿主的通用单命令发布器。

安装完成后刷新当前 Codex 的技能发现环境。如果当前会话没有识别新 skill，由 Codex 指明已安装位置并按宿主支持的方式刷新或开启新会话。刷新不会改变审批，也不能用于绕过执行拒绝。

## 备用：手动安装

1. 解压 Windows 使用包到新建的可写目录。
2. 检查 Node 24.18 或以上的 24.x x64 已安装。
3. 运行 `Install.cmd`，或让 Codex 运行 `source/collaboration/install-package.mjs`。
4. 将安装目录、材料目录与目标 Chat 告诉 Codex，让它完成自有服务初始化和绑定。

使用包的安装入口校验 `PACKAGE-MANIFEST.json` 中的文件哈希。仓库源码的 `Install.cmd` 用于开发时更新已管理的 skill，不代替首次平台连接。

## 日常使用

已配置账号直接复用私人服务和绑定。用户指令或项目规则允许后，Codex 自动选择必要材料、发送、等待、补充和取回；用户不用编辑 JSON、逐次选文件或搬运结果。

例如：

> 请让已绑定的 Chat 审核这次改动，然后取回结果继续修改。

> 请让已绑定的 Chat 生成一张雨后山巅武侠对决图，并取回原图。

任务内容允许 Codex 协作时可以沿用许可范围；没有安排协作时不自动发送材料。材料授权可覆盖当前项目或明确目录，但发送仍只选必要材料。

缺材料会由 Chat 提交需求，Codex 在原授权目录补充。改变目录、目标或账号时告诉 Codex；未完成任务要先完成、明确终止或按状态续等，不能直接抢占绑定。

## 多账号

本机为每个账号保存独立的私人服务和 Chat/材料目录配置。切换账号后，Codex 先核实当前实际身份，再恢复对应绑定；仅改配置文件不会完成平台登录。真实第二账号切换尚未验收，见验证记录。

## 当前必须由用户完成的步骤

- 指定材料范围、安装位置和目标 Chat。
- 必要的本人登录、平台应用连接及安全确认。
- 缺 Node 时确认官方安装。

平台工具选用、账号资格、网络和服务发布能力是外部条件。本项目不能代替平台授予权限，也不包含通用账号凭据。首次完整配置尚未在独立新用户账号上复测，日常当前账号协作已经实测。

## 附件与恢复

当前单个附件最大 16 MiB；从开始上传计约一小时到期，读取不延长到期。接收后程序删除临时对象并确认不可读取。过期/删除会拒绝访问；闲置对象的物理清理由访问或删除触发，不承诺精确时刻的后台销毁。

超时保留原任务包和状态，Codex 加载同一包续等。发送确认不明时不盲目重发，图片自动导出最多一次。结果保存到独立本机目录，不覆盖已有文件。
