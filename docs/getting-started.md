# 使用指南

这是 Codex 与 Chat 的消息、材料和结果传输工具。任务内容、专业处理方法及输出格式由你决定。可直接安排一次任务，也可在项目规则中允许 Codex 使用 Chat 协作。

## 首次安装

无需先解压。把 ZIP、它的本机路径或下载链接交给 Codex，说明：

1. 安装位置。
2. 允许发送材料的目录，可指定当前项目。
3. 桌面端 ChatGPT 会话名；重名时补充项目名，也可给链接。

> 请安装到 D:\Tools\codex-chat，材料允许用 D:\Projects\my-app，目标用桌面端的“方案讨论”。

Codex 检查环境、依赖和包哈希，安装 skill，配置你自己账号的私人服务并保存绑定。安装目录和材料目录可不同；已有配置先核实再复用。无需编辑 JSON、查 clientId 或复制事务参数。

首次登录、平台授权或缺 Node 时的官方安装确认由本人完成。服务发布与应用连接分别核验；自动入口受限时，Codex 会指出具体页面和动作，可能需要你到“插件 → 个人 → 由你创建”安装或连接本账号应用。

需要 Windows x64、Node 24.18 或以上的 24.x x64，以及 Codex 桌面原生消息、当前账号可用的 Sites 发布和私人 MCP 连接能力。缺少平台入口时不能保证完成安装。也可手动解压到新建可写目录、运行 Install.cmd，再告诉 Codex 上述三项。

## 日常使用

复用原连接，无需重新安装、发布服务或创建 MCP。直接向 Codex 说明目标、必要材料和交付要求，例如：

> 把这份方案发给 Chat 审核，取回修改建议后继续。

> 让 Chat 为迁移工作写实施计划，重点写依赖关系和回滚条件，返回文档。

> 向 Chat 逐条发送这五个画面的生图指令，图片我自己下载。

Codex 编写简短业务请求；程序生成协议字段，处理材料传送、等待、下载校验和清理。Chat 缺材料时由 Codex 在授权目录内补充，Chat 不能自行读本机磁盘。你不必逐次选择 skill 或搬运结果；实际应用工具是否可用受平台环境影响，缺失时会报告。

生图是可选的仅发送模式：最多 16 条，上一轮结束后发下一条，最后一条送达即返回。用户在 Chat 查看和下载；送达不等于出图成功。另行要求“取回刚才的原文件，不重新生成”时使用普通文件通道，仍受 Chat 实际导出能力限制，不保证自动导出每次成功。

同一 Codex 可以同时与多个 Chat 协作，直接说“让‘方案审核’审这份方案，同时让‘实施计划’规划后续工作”。Codex 按会话名登记目标，每项保存自己的材料目录、任务和结果；目录可以相同。单次最多并行 8 个不同 Chat，同一 Chat 继续逐项执行，另一 Codex 不共享该 Chat。

默认目标仍可沿用或更换。旧任务未完时可说明“先保留暂停”；恢复继续取结果，不重复发送，也不会撤回已发消息。当前并行范围为同一账号，多账号真实测试仍延期。

## 更新与限制

把新版 ZIP 交给 Codex，说明“更新到原位置，保留账号、材料目录、Chat 绑定和暂停任务”。通常无需重建私人服务或连接。

每位用户使用自己的固定地址远程服务；选定附件从上传开始约一小时失效，单文件最大 16 MiB，成功取回后清理。原文件大小和哈希由程序核验；文件传输成功不代表 Chat 实际看到了图像或听到了音频。

等待在同一工具程序内完成：普通任务约每 30 秒查正式结果，每五分钟无结果再核对对应轮次。默认单次 10 分钟、最多 15 分钟，超时保留状态可续等；宿主续取仍可能产生模型请求，没有闲置会话事件唤醒。

新用户首次配置及真实多账号完整验收尚未完成，音频感知未通过；图像预览存在平台限制。实际记录：https://github.com/313715295/codex-chat/blob/main/docs/validation.md
