# 实现与执行边界

这是传输工具；业务目标、专业方法和交付格式由使用者决定。私人 MCP 通过 get_collaboration_entry 提供入口说明，并直接暴露任务、附件和结果工具；程序 describe() 和 MCP 工具说明提供参数及共同规则，无需独立 skill，不另建业务工作流。

桌面原生消息发送/读取 → Chat 对话 → 用户自有私人 MCP → 结果/原文件 → Codex 下载核验和继续任务。

## 本地入口

job-entry.js 编排准备、绑定检查、执行占用、发送、等待、收发和记录；host-runtime.js 校验账号、通道、任务版本和回执，处理普通协作与可选生图消息队列；attachment-host-runtime.js 编排附件工具；attachment-local.mjs 在本机按授权目录执行原文件访问和完整校验。

functions.exec 内加载入口和模块，工具结果仅在程序变量中处理，正常执行不回显完整源码、空查询或文件分块。原生账号认证和桌面消息工具仍需要 Codex 宿主桥接。现有入口缺少桥接时，在文件准备或远端操作前返回 HOST_BRIDGE_REQUIRED；当前没有可验证的独立 MCP→宿主回调，不把入口元数据称为已注册的统一 MCP 工具，也不把 CLI 当作独立平台账号客户端。

模型提供任务请求；prepare.mjs 生成固定任务包，bindings.mjs 保存账号、Chat、目录与执行占用，状态文件支持恢复并防止重复发送。详细 outcome.json 保存在本机，宿主应只回显必要结果与文件位置。验收期间统计脚本不是日常运行依赖。

程序自身不请求模型 API；工具宿主的续取可能产生模型响应。当前不是常驻守护程序，也不提供闲置会话自动唤醒。

普通审核、规划约每 30 秒查询正式结果，每五分钟无结果才核对对应 Chat 轮次，对应轮次存在助手回复且完成时最多提醒补交一次；user-only completed 占位不算处理完成，不在任务前额外发送能力探针。图片参考材料或队列异常时按需轻量查探；独立 Chat 探针会产生额外消息与推理，不随每条生图指令执行。当前服务只提供结果即时查询，事件订阅未开放投递；单改服务端挂起不能消除宿主的模型续取。

统一入口默认等待 10 分钟，单次最多 15 分钟。超时保留原任务包和状态，可加载同一任务续等；发送确认不明时不盲目重发。结果写入独立目录，不覆盖已有文件。

## 结果与附件服务

source/results-attachments-template 通过用户自有 Sites 能力发布，D1 保存任务/结果，R2 保存选定附件，平台认证标识参与每项访问隔离。干净 hosting.json 仅声明 DB、BUCKET 和 MCP 能力，没有用户的 project_id。

任务由 taskId、revision、assignmentReceipt 和返回回执关联。完成结果需精确匹配，文本路径和附件元信息不代表文件已传输。Chat 缺材料以 needs_materials 提交具体需求，由 Codex 在授权目录补充新版本。

程序按实际材料生成消息：任务标识只声明一次，已提供正文不重复读取，未上传输入附件时不附预览步骤。materialsRead 仅记录收到的本次输入；输出原文件使用 attachmentIds，对应关系放入 summary 或 findings.message。无输入时 materialsRead=[]，不创建占位材料。仍拒绝输出文件冒充输入证据，未放宽身份、来源或哈希校验。

附件使用同一双向通道，最大 16 MiB，服务端块最大 256 KiB。本地宿主下载采用 40 KiB 块、最多 3 个只读预取，顺序写盘并核验；桥接代码遵守现有 64,000 字节限制，不通过换通道放大请求。

图片和音频参考材料由 Chat 先尝试预览，只有实际可感知时才能据此处理；需保存、解析或字节验收时再下载核验。提示词不再要求每次视觉任务重复下载整文件；本地和服务端的传输校验保持，预览元数据不作为感知通过证据。

附件从开始上传计约一小时到期，读取不续期。接收后程序删除临时对象并确认不可读；过期或删除会拒绝访问，闲置对象的物理清理由访问或删除触发，不承诺精确时刻的后台销毁。

## 图片

当前源码将生图改为用户可选的仅发送模式。imagePrompt 是单条指令，imagePrompts 是最多 16 条的队列；本地包固定 imageDelivery=manual。沿用账号绑定和平台所有者核验、原生目标检查及执行锁，不登记远程任务、不要求目标 Chat 暴露 MCP 附件工具、不查询或取回图片结果。

单条指令收到原生消息回执就返回。多条通过原文、发送时间窗口及轮次 ID 对应前一条；同轮 completed、对话 idle 后才发送下一条。约 30 秒一次的调度检查在程序内进行，最后一条送达即返回 sent，generationVerified=false。用户在 Chat 查看和下载；不发送导出或提交结果的后续消息。轮次结束不证明实际出图成功。超时保留未发项，回执丢失时停止且不重发。

已发布 v0.3.5 的自动图片回传曾有成功记录，后续复测不稳定。历史运行包保留，当前统一入口拒绝续跑旧图片自动回传；兼容代码仅用于历史回归，不作为新请求的执行分支。

用户明确要求取回已生成文件时，可另建普通 receiveAttachments 请求，使用同一文件传输通道；这不恢复生图队列的自动导出。成功取回受 Chat 当轮附件工具及原文件导出能力限制。

## 多任务和安全

以 Codex 会话为协作主体，保留原默认绑定，同时按 Codex/当前账号/Chat 登记多个目标。请求可显式选择目标；相同材料目录允许复用。任务包固定目标、目录、账号与通道，任务编号加入目标命名空间，不同 Chat 的同名请求不会串线。

runMany 在同一程序内先完成所有本地范围检查，再并行运行最多 8 个不同 Chat；各自保存包、状态、输出和执行租约，一项失败仍返回其他项结果。桌面发送请求与共享的本地文件桥接各自串行处理，远端处理和等待并行；同一 Chat、输出目录重叠或跨账号批次提前拒绝。当前没有通用后台队列，单个 Chat 的后续任务须等前项结束。

待完成任务默认阻止切换。用户要求保留暂停时，pause 只接受没有运行中 waiter 的待办，原子保存任务、绑定和通道快照，再允许更换目标；不改原任务包、状态或远端结果，不撤回 Chat 消息，也不把暂停记作完成。暂停记录按 Codex 会话与 packetId 保存，原 Chat 继续独占，原任务编号不允许新任务重用。多目标任务 resume 只恢复自己的路由与占用，其他任务可继续；旧单目标包仍要求没有其他待办并恢复原绑定。随后由统一入口核实身份并从原状态续等。运行中的等待、其他 Codex 的任务、错误账号和发送不明状态不能借暂停或恢复绕过保护。

保留本地路径/junction 检查、禁止敏感路径、固定授权根、账号和服务一致性检查、包哈希、执行锁、防重复发送、附件到期和删除验证。当前无本地 reader 或临时隧道。没有认证、通道或宿主工具时明确失败，不以公开路径/共享后台代替。
