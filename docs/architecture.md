# 实现与执行边界

桌面原生消息发送/读取 → Chat 对话 → 用户自有私人 MCP → 结果/原文件 → Codex 下载核验和继续任务。

## 本地入口

job-entry.js 编排准备、绑定检查、执行占用、发送、等待、收发和记录；host-runtime.js 校验账号、通道、任务版本和回执，处理原生消息及一次自动图片导出；attachment-host-runtime.js 编排附件工具；attachment-local.mjs 在本机按授权目录执行原文件访问和完整校验。

functions.exec 内加载入口和模块，工具结果仅在程序变量中处理，正常执行不回显完整源码、空查询或文件分块。原生账号认证工具仍需要 Codex 宿主桥接，不能把本地 CLI 当作独立平台账号客户端。

模型提供任务请求；prepare.mjs 生成固定任务包，bindings.mjs 保存账号、Chat、目录与执行占用，状态文件支持恢复并防止重复发送。详细 outcome.json 保存在本机，宿主应只回显必要结果与文件位置。验收期间统计脚本不是日常运行依赖。

程序自身不请求模型 API；工具宿主的续取可能产生模型响应。当前不是常驻守护程序，也不提供闲置会话自动唤醒。

## 结果与附件服务

source/results-attachments-template 通过用户自有 Sites 能力发布，D1 保存任务/结果，R2 保存选定附件，平台认证标识参与每项访问隔离。干净 hosting.json 仅声明 DB、BUCKET 和 MCP 能力，没有用户的 project_id。

任务由 taskId、revision、assignmentReceipt 和返回回执关联。完成结果需精确匹配，文本路径和附件元信息不代表文件已传输。Chat 缺材料以 needs_materials 提交具体需求，由 Codex 在授权目录补充新版本。

附件使用同一双向通道，最大 16 MiB，服务端块最大 256 KiB。本地宿主下载采用 40 KiB 块、最多 3 个只读预取，顺序写盘并核验；桥接代码遵守现有 64,000 字节限制，不通过换通道放大请求。

## 图片

新图请求的第一条消息只有 imagePrompt。程序核对最新用户消息、原生发送时间窗口及同轮结束线索；仅时间过去或裸 idle 不足以发送导出。第二条点名已核实私人服务的应用名称，仅导出上一轮原图，带任务字段及真实附件/结果提交要求。自动导出最多一次，不确定时不盲目重发。

## 多任务和安全

每个 Codex 同时绑定一个 Chat，Chat 目标独占；不同绑定的材料目录可相同。配置可按账号保存，切换前核对真实身份，待完成任务阻止切换。

保留本地路径/junction 检查、禁止敏感路径、固定授权根、账号和服务一致性检查、包哈希、执行锁、防重复发送、附件到期和删除验证。当前无本地 reader 或临时隧道。没有认证、通道或宿主工具时明确失败，不以公开路径/共享后台代替。
